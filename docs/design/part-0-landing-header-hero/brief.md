# Landing Header And Hero Brief

**Approved by:** Product owner in the active KCMS planning discussion

**Implementation mode:** Direct Codex design using the accepted UX and web-design
skills. OpenDesign generation was explicitly waived by the product owner after
the brief, flow, palette, copy direction, and references were agreed.

## Job

A first-time Page owner, manager, or moderation staff member should understand
what KCMS does and start requesting access without needing documentation.

## Core Path

```text
Landing -> understand the promise -> Request access
        -> returning user -> Sign in
```

## Content Hierarchy

1. KCMS identity and language control.
2. A direct Khmer-comment moderation promise.
3. Human-control disclosure.
4. Request Access primary action.
5. Comment Pathway product proof.

## Scope

This slice includes only the responsive header and hero in English and Khmer.
Request Access, Sign In, and the remaining landing sections are later slices.
